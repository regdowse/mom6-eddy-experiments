# Beta pilot preparation

`beta-pilot.yaml` is a local, provisional generator plan, not an instruction to submit jobs. It pins baseline commit `c488f9730902c1002fe3c3b667b10100c3c884c7` and uses absolute paths on Gadi. Reassess the start commit after reviewing and committing later configuration changes; the plan itself is separate from that starting commit. The test path is temporary scratch storage, and generated archives require an agreed retention policy.

Before generation, build the common geometry and run `python initialisation/prepare_beta_pilot.py`. This creates non-overwriting `input/cases/beta_0` and `input/cases/beta_33s` folders and their separate generation records under `input/case-provenance/`. Generated inputs are ignored by Git. Initial field arrays are equal for the agreed fixed centre f, but NetCDF metadata and case-specific balance diagnostics differ. Keep both case folders and records immutable after preparation. Refer to the respective `case.json` and `initialization-provenance.json` for checksums; actual Payu run manifests must also be verified and retained.

The plan proposes a two-day cold-start smoke test via `input.nml`; this is for runtime and diagnostics checks, not a tilt-evolution experiment. The plan sets each branch's Payu `input` to its matching directory as well as its beta. `keep_uuid: false` and `new_uuid: false` avoided a duplicate control identity in the scratch test, while still assigning distinct identities to new branches. Verify UUIDs and archive paths, including on repeated generation; do not use these settings blindly for a missing existing archive. Payu's `archive` symlink refers only to the checked-out branch. Branch commits and identities, not folder names alone, identify experiments.

The ACCESS development source tested was commit `8cbec23b62adb71c15f19e268d90f0542acad280`; PyPI generator 1.0.0 rejects mom6. A durable pinned tool environment and output retention location remain to be established. No scientific pilot has been submitted. For a first model pilot, inspect effective grid and Coriolis output, input/execute checksums, initial adjustment and vorticity diagnostics. `wd` is diapycnal velocity. The provisional executable and analytic grid template require runtime verification.

## Preflight results, 26 November 2026

The two case NetCDF files were independently generated from the committed provisional baseline and have identical numerical arrays; beta attributes and balance diagnostics differ. The center-f initialization check reports relative geostrophic residuals of 0.00274347 for beta zero and 0.0114177 for 33°S beta; the latter carries the expected centre-f-approximation warning. These are offline diagnostics, not model-equilibrium or runtime checks.

A disposable local clone of baseline commit `c488f9730902c1002fe3c3b667b10100c3c884c7`, with only its laboratory path changed to scratch, was used to test the generator plan. The generated branches selected the correct case folders, had unique UUIDs and two-day `input.nml` settings, and matched the beta metadata and SHA-256 hashes of all five files in each case folder. Both initial-state numerical arrays matched. The generator also changed jobname to its checkout directory name. This was branch preparation only: Payu setup, staging, runtime initialization, archive outputs and runner submission were not tested.

Before any model job: verify the executable checksum and build, review input and provenance retention, ensure the intended generator/environment and committed base match this plan, generate cases in the intended workspace and inspect their actual git diffs, UUIDs and archives. Compare the actual MOM6 grid and wet masks against the analytic initializer template, and inspect runtime Coriolis and daily diagnostic files. A two-day smoke test is insufficient to assess scientific tilt or boundary influence.
